## Operating rule

Read the task-specific Job Envelope before acting. If a necessary action is
unknown, denied, requires approval, exceeds budget, or touches a protected
path, stop and create a decision request. Do not work around the boundary.

## Allowed actions

- `code.modify`: Implementation requires changes inside the declared writable paths.
- `git.push_feature_branch`: Reviewable feature branches are required for human merge approval.
- `deploy.staging`: Staging is the autonomous acceptance environment.
- `deploy.production`: The protected-branch merge approval authorizes the contracted production release; deployment still requires evidence and readback.

## Human approval required

- `git.merge_master`: Humans retain the final protected-branch decision.
- `project.vision.activate`: An Agent may propose vision changes but cannot activate them.
- `project.contract.activate`: A run cannot grant itself new authority.

## Denied actions

- `database.destructive_migration`: Autonomous destructive migrations are outside the first-phase scope.
